Enterprise Guarantees

Business Invariants & Integrity Rules

Core engineering constraints enforced at database and application layers to prevent financial drift, stock discrepancies, and unauthorized operations.

INV-01

Double-Entry Accounting Balance

Every financial transaction enforces SUM(debit) == SUM(credit). Unbalanced journal entries are rejected by service validation and PostgreSQL check constraints.

INV-02

Perpetual Stock Ledger

Every stock movement (inbound GRN, outbound dispatch, inter-warehouse transfer, or physical count adjustment) writes an immutable transaction log record.

INV-03

Multi-Branch Isolation & Governance

Operational mutations and queries are strictly scoped by branch_id and verified against user membership tables. Inter-branch movements generate bilateral clearing entries according to PSAK 65 / IFRS 10.

INV-04

Granular RBAC & Permission Matrix

Access control checks every API mutation against a strict module:action permission matrix (102 permissions across 17 modules and 6 actions), enforced both in Chi backend middleware and Next.js layout routes.

INV-05

Comprehensive Audit Trail

Mutations capture structured audit logs containing actor_id, branch_id, action, resource, pre-state, post-state JSON diffs, and precise UTC timestamps.

INV-06

Pure DDL Database Migrations

Goose migration scripts contain only DDL statements (CREATE, ALTER, INDEX). Seed data and initial enterprise fixtures are isolated in a standalone Go CLI runner.
